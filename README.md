# DormHub — інтерфейс гуртожитку

Десктопний застосунок на Python (CustomTkinter) для гуртожитку: чати, оголошення, події, заявки на ремонт.
Дані застосунку читаються з PostgreSQL. `data/mock_data.py` більше не використовується під час
роботи програми.
Після запуску введіть ім’я та прізвище наявного активного користувача PostgreSQL.
Пробіли на початку й у кінці ігноруються, регістр перевіряється засобами PostgreSQL.
Заблоковані акаунти та неоднозначні збіги не допускаються до входу.
Кнопка «Вийти з акаунта» повертає на екран входу.

Адміністратори визначаються за таблицею `dorm_admins`: у профілі відображається
«Адміністратор». Наприклад, у `db.sql` такий акаунт — **Сергій Мельник**.
Наявні призначення інших адміністраторів збережено. Додаткових міграцій для входу не потрібно.
Вхід за ім’ям і прізвищем — тимчасовий режим без пароля.

## Запуск на Windows

1. Встановіть Python 3.10+ з python.org (під час встановлення поставте галочку **Add python.exe to PATH**).
2. Розпакуйте папку й двічі клацніть **`run.bat`**. Перший запуск сам створить середовище й встановить бібліотеку.

Або вручну в терміналі:
```
pip install -r requirements.txt
python main.py
```

## Підключення PostgreSQL

1. Створіть базу даних PostgreSQL.
2. Виконайте у ній скрипт `db.sql`.
3. Створіть файл `.env` на основі змінних:

Скрипт також створює окремий постійний чат для кожної кімнати та таблицю повідомлень.
**Увага:** `db.sql` повністю перебудовує таблиці й видаляє попередні дані. Це скрипт
створення демонстраційної бази, а не міграція зі збереженням даних. Перед виконанням
у pgAdmin збережіть резервну копію, якщо поточні записи потрібні. Скрипт виконується
однією транзакцією; навчальні приклади змін і видалення даних з кінця файлу прибрано.

```
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=dormhub
DB_USER=postgres
DB_PASSWORD=ваш_пароль
```

Файл `.env` не потрібно додавати до Git.

## Оголошення, події та адміністрація

Після оновлення виконайте `pip install -r requirements.txt` (додано `tzdata` для
київського часу у Windows), виконайте актуальний `db.sql` у pgAdmin й запустіть програму.

- **Оголошення:** перегляд публікацій свого гуртожитку; адміністрація створює,
  редагує та видаляє їх.
- **Події:** дата й час Києва, місце, опис, місткість; запис і скасування участі.
  Після початку події нова реєстрація закривається.
- **Мої звернення:** заселений мешканець створює ремонтне звернення й бачить свої
  звернення, відповіді та історію статусів, зокрема після переселення.
- **Адміністрування:** доступне лише адміністраторам (`dorm_admins`), наприклад
  **Сергій Мельник**. Вкладки: «Мешканці», «Кімнати», «Поселення», «Звернення».
  Мешканця спочатку додають без кімнати, потім поселяють. Є пошук, фільтри за кімнатою
  та статусом акаунта, редагування даних і блокування / розблокування з причиною.
  Кімнати мають місткість та доступність для поселення. Кімнату можна закрити для
  нових поселень, не виселяючи поточних мешканців.

Права перевіряються в операціях доступу до даних. Адміністратор керує лише своїм
гуртожитком; змінювати ролі через ці форми не можна. Поселення, переселення й виселення
виконуються транзакційно, з історією, відповідальним адміністратором і причиною;
переповнення кімнат захищене блокуванням записів. `students.room_id` оновлюється в тій
самій транзакції, тому кімната, сусіди й доступ до чату відповідають поточному поселенню.
При створенні кімнати автоматично створюється її чат. Оновлення списків — кнопкою
«Оновити» або при переході між вкладками.

Звернення мають окремі таблиці `maintenance_requests` і `request_status_history`;
`applications` і надалі містить лише заявки на вакансії. Окремі місця в кімнаті,
продовження строку проживання, призначення майстрів і сповіщення ще не реалізовані.
Тимчасовий вхід за ім’ям і прізвищем та пряме підключення до БД залишаються поточними
обмеженнями застосунку.

## Структура

```
main.py                 точка входу
data/
  mock_data.py          застарілий файл прикладів, не використовується застосунком
  repository.py         функції доступу до PostgreSQL
ui/
  app.py                головне вікно, бічне меню, перемикання сторінок
  theme.py              спільні кольори/шрифти
  module_a/             Люди і проживання: profile.py, room.py
  module_c/             Паркінг та інші розділи
```

Кожен з команди працює у своїй папці `module_*` і у своєму розділі `repository.py`,
тому конфліктів у Git майже не буде.
